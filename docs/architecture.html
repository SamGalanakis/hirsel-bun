Current End State

Hirsel is now backend-first.

The backend is the product. The desktop app is only a thin shell that stores the backend URL and API key, then loads the backend-served Datastar UI. Durable chat, orchestration, workers, routes, and artifacts all live on the backend.

System Shape

flowchart LR User[User] Shell[Desktop shell / browser] Connect[Backend connect bootstrap] WebUI[Datastar UI routes] Core[Project / route / work tree / chat state] Orch[Channel + branches] Workers[Sandbox workers] Artifacts[Virtual artifacts / focus / retained context] User --> Shell Shell --> Connect Connect --> WebUI WebUI --> Core Core --> Orch Orch --> Workers Orch --> Artifacts Workers --> Artifacts

Important: closing the UI no longer stops backend-owned work. User messages and project sync are queued durably on the backend.

Desktop shell

Minimal Tauri wrapper.

  • Stores backend URL + API key locally
  • Checks backend health
  • Loads backend UI in a webview

Backend UI

Server-rendered HTML with Datastar.

  • Explicit pages and actions
  • SSE for live updates
  • No generic client RPC bridge

Execution layer

Backend-owned orchestration and workers.

  • Durable Shepherd queue
  • Background sync / orchestration tasks
  • Workers spawned from the backend

UI Routing

The live product path is now page/action/SSE based.

Path type Examples Purpose
Pages /connect, /app, /app/projects/:id Initial HTML and navigation targets
Actions /connect/session, /app/projects/:id/chat/send, /app/projects/:id/sync State-changing POST flows
Streams /app/projects/:id/stream, worker detail stream Incremental Datastar patches over SSE

State Model

Project / route / work tree

Projects contain routes. Routes carry the durable line of work. Each route has a hierarchical work tree instead of the old board/node canvas model.

Artifacts

Focus view and retained context are backend-owned artifacts. The focus view is served as a dedicated document and embedded in the main project page.

Shepherd chat

User messages are queued on the backend. The UI reads transcript and queue state from the server instead of owning turns locally.

Worker state

Workers and their events are backend state. The Datastar app subscribes to streamed updates rather than polling a client-side store.

What Was Removed

  • The Solid SPA and its client stores/hooks
  • The active /api/ui/invoke bridge
  • The old profile-based local/remote client split
  • The old run-centric user model
  • The board/specflow canvas as the active planning surface
