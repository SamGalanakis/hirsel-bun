Why this is interesting

Type blocks = composable tasks

Each task is a physical block of metal type. You arrange them in a composing stick to build a galley. The metaphor makes decomposition tangible — you can see how many blocks make up a spec, and each block is a discrete, movable unit that must be set before the galley can print.

Ink coverage = completion

A fully inked galley is ready to pull a proof. Partial ink coverage means the roller hasn't finished its pass — some blocks are set but not yet pressed. You see completion as a physical property of the surface, not as a number in a progress bar.

Rollers = worker pressure

The press roller sweeping down a galley is the worker executing tasks. It applies force uniformly across all set blocks. Multiple workers are multiple rollers, each pressing a different galley in parallel. The mechanical rhythm of the press maps to the dispatch cycle.

Proofs = delivery

Pulling a proof is the moment the work becomes real — ink transfers from type to paper. Delivery is the same: code transfers from the workspace to a pull request. A validated galley marked "good to print" is a spec ready for delivery. The proof sheet is the PR diff.
