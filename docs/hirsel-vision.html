04 · execution mode

Derived, not stored

Execution mode is a lash-runtime internal. Hirsel picks it at thread spawn based on whether the cap set includes a meta-capability. Nobody stores it. Nobody picks it in the UI.

caps
capabilities[]
→
contains
spawn_thread?
→
mode
Rlm · Standard
yes → Rlm
LLM emits lashlang programs. Runtime parses, compiles, executes. Tool calls become lashlang call statements; spawn_thread becomes start call spawn_agent.
no → Standard
LLM uses native tool-call protocol. Same path as today's shepherd/thread runtime. Nothing changes.
05 · coordinator flow

From chat to child threads and back

sequenceDiagram
  autonumber
  actor U as user
  participant C as coordinator thread
  participant L as lash runtime
  participant H as Hirsel SubagentHost
  participant K1 as child thread A
  participant K2 as child thread B
  participant KG as knowledge graph

  U->>C: open chat · pick "coordinator" · write objective
  C->>L: turn begins (Rlm mode, spawn_thread in caps)
  L->>C: emit lashlang program
  Note over C,L: for t in tasks { h = start call spawn_agent ... }
  L->>H: spawn_agent{task_name, capability}
  H->>K1: create thread row (parent_id = C.id, binding, caps)
  H->>K2: create thread row (parent_id = C.id, binding, caps)
  K1-->>H: finish {artifact_a}
  K2-->>H: finish {artifact_b}
  H-->>L: results available
  L->>C: results = await handles
  C->>C: reduce / merge
  C->>KG: (optional) curated kg.upsert for durable findings
  C-->>U: final output

Every child is a real thread row — observable, resumable, inspectable in the UI during and after the run. Parent–child relationships persist in the thread table. Every transcript flows into the KG via the librarian as usual.

06 · primitives

Four decompositions beyond spawn+await

These are additions to the lashlang stdlib. Each widens the decomposition space in a way a tree of spawns cannot.

quorum
best-of-N with agreement
// spawn N variants, keep k that agree, merge.
let winners = quorum(
  k_of_n: 3/5,
  prompt: "classify this node's kind",
  agree_by: "exact-match"
)
finish winners.majority()
merge
DAG recombination
// two branches explored, recombine into one artifact.
a = start call spawn_agent { task: "approach-A" }
b = start call spawn_agent { task: "approach-B" }
[ra, rb] = await [a, b]
synth = merge([ra, rb], strategy: "synthesize")
finish synth
fix
iterate to stability
// run step until the join of prev+next == prev.
answer = fix(state: seed) {
  next = call refine { state }
  state = join(state, next)
} until stable
finish answer
graph.pheromones
lock-free KG coordination
// sub-threads annotate, others read, decay clears stale.
graph.mark(node, scent: "needs_review", weight: 0.7)
hot = graph.sniff(scent: "needs_review", top: 5)
for n in hot { call spawn_agent { binding: n } }
graph.evaporate(half_life: "1h")
07 · memory

Two tiers, one rule

tier · ephemeral
lashlang VM
  • Variables, handles, loop accumulators
  • Lives for one coordinator turn
  • In-process, typed
  • How children pass results to parents
tier · durable
knowledge graph
  • Facts, decisions, documents, relations
  • Survives threads, shared across them
  • Searchable via search_context
  • Librarian ingests transcripts passively
Rule. Children return via finish, not via KG writes. KG writes are intentional and curated — "this fact matters beyond this run." Otherwise the graph bloats and decomposition slows down.
